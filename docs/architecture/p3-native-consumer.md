## Guard-First and Disabled Posture Invariants

1. **One switch, nothing installed**:
   - The only switch is `first_app_p3_host.WRITES_ADMITTED = False` (D6.4: a reviewed code change turns it on). `first_app_p3_native` keeps no copy of it.
   - `DEFAULT_NATIVE_BOUNDARY`, `DEFAULT_NATIVE_HOST_JOIN`, and `DEFAULT_WORKER_OBSERVER` are `None`; `verify_canonical_supplier_bindings()` raises if any is set.
   - `compose_disabled_consumer_service(**kwargs)` enforces `writes_enabled=False` and raises `ValueError` if called with `writes_enabled=True`.
   - Candidate bindings stay unset in the source. `temper_ai.runner.admission` has no default bindings, and every runner entry point (`execute_workflow`, `cmd_run_workflow`, `_scan_and_dispatch`, `_claim_row`, `_cmd_validate`) takes `candidate_bindings` keyword-only, defaulting to `None`. In `temper_ai/`, `configs/`, `scripts/`, `p3_host_contracts/` and `p3_source_closure/` outside `temper_ai/p3_authority/`, seven facts hold:
     1. every `candidate_bindings` parameter, of a function or a lambda, is keyword-only and defaults to `None`, and no `*args` or `**kwargs` takes that name;
     2. a value handed on (a `candidate_bindings=` keyword, a `"candidate_bindings"` dict key, or `bindings=` to `submit_candidate`) is the calling function's own untouched `candidate_bindings` parameter, and nothing is splatted into `submit_candidate`; the one exception is the server's state reader, `routes._start_run`'s `bindings = _candidate_bindings()`: a direct statement of `_start_run`'s body, placed before the statement holding the call, and the value's only binding there (its name is no parameter of `_start_run` and is not declared `global` or `nonlocal` in it);
     3. nothing stores `candidate_bindings`: no attribute store, no module- or class-level name of that name (a field left `None` or only declared included, and a class inside a function counts), no `global candidate_bindings`; and the string `"candidate_bindings"` appears only as a `.get`/`getattr`/`hasattr` read or a dict key fact 2 checks, so `setattr` (aliased too), `setdefault`, `operator.setitem`, subscript stores and `dict(zip(...))` are all seen;
     4. only `first_app_p3_native.py` names `P3CandidateBindings`, `P3AuthorityComposition`, `P3AuthorityService`, `compose_p3_authority` or `compose_disabled_consumer_service` (as a name, attribute, import or `getattr`/`hasattr` string), and there only `compose_disabled_consumer_service`, which refuses writes, calls the composer;
     5. `submit_candidate` appears only as a direct call's function or a plain un-aliased import (no alias, `functools.partial`, `getattr` string or rebinding);
     6. the state reader fact 2 trusts is pinned: in `routes.py` the only binding of `_candidate_bindings` is one undecorated plain module-level `def` with no parameters and no `yield` or `await`, every `return` in it gives `None` or `vars(S).get("candidate_bindings")`, where `S` is `_state()` or a name the reader binds exactly once, by `S = _state()`, and declares neither `global` nor `nonlocal`; `_state` is one undecorated plain module-level `def` there; `vars` is not rebound there, and no scanned code imports `builtins` or names `__builtins__`. With fact 3 holding, that read gives `None`;
     7. nothing shadows or replaces the state reader: the name `_candidate_bindings` appears only in `routes.py`, as that `def` and as the function of calls with no arguments; no parameter, attribute (`routes._candidate_bindings = ...`), keyword, import, `def`, class, capture, `global` or `nonlocal` declaration or string (`setattr(routes, "_candidate_bindings", ...)`, `globals()["_candidate_bindings"]`) of that name appears anywhere scanned.

     `tests/test_architecture/test_candidate_bindings_source_facts.py` checks these facts by reading the source, with a planted twin for each route it must catch and clean twins it must pass. Nothing checks them at import. Not seen: names built at run time (`setattr(obj, name, ...)`, `import_module` strings), values loaded from data at run time, string annotations, an attribute named `_state` set on the routes module from elsewhere (`_state` is a common attribute name, so it is not banned), and a value passed by position to a parameter of another name (`is_designated(workflow, bindings)` only reads; `submit_candidate` takes `bindings` keyword-only).
2. **Short-Circuit Before Input Inspection (`H1`)**:
   - While `WRITES_ADMITTED` is `False`, `open_host`, `settle`, `run_row`, and `join_native_host_row` return `BLOCKED` with `reasons=[WRITES_OFF]` (or return immediately in `settle`) before inspecting `host`, `row`, clocks, sleeps, or filesystem paths.
   - With writes on, the host-row join (`join_native_host_row`, `join_admitted_host_row`) still returns `BLOCKED` for every row with `NATIVE_BOUNDARY_NOT_WIRED`. It takes no boundary argument and never runs `run_row` in place of a native check, so its result can't be read as native-verified.
3. **Offline Consumer Result Join (`H2`)**:
   - `join_offline_supplier_results(...)` is a pure join of supplier results from `P3AuthorityService` (`before_create`, `before_checker`, `before_request`, `before_admit`, `before_execute`, `before_count`), `NativeHostJoin` (`lookup_occurrence`, `verify_publication`, `receive`), `p3_source_closure.compare_loaded_source`, and `WorkerObservationAdapter` (`observe`, `root_observer.verify_both_roots`). The harness that drives those calls (including the state-changing `record_admitted_occurrence` and `receive`) lives only in the test file, over the in-memory providers.
   - Even when every injected offline supplier stage returns `AcceptedData` and `SourceClosureComparison(disposition="MATCH", reasons=())`, the outer evaluation remains `status="UNQUALIFIED"` and `count_eligible=False` while `WRITES_ADMITTED` is `False`. It never returns `status="PASS"`. Consumers key on `status` and `count_eligible` only: `inner_count_decision` is the supplier's raw `before_count` decision and can say `PASS` while the join is `UNQUALIFIED`.
   - Any refusal in authority, worker observation, both-root verification, or native receive, or any `SourceClosureComparison` with `disposition != "MATCH"` or non-empty `reasons`, transitions the joined status to `"BLOCKED"` and records the exact refusal codes, phases, and closure reasons.
4. **Unresolved Native Obligations (`N1–N8`) and `R1–R5` Preservation**:
   - All eight native obligations (`N1` through `N8`) remain `"UNRESOLVED"`.
   - Host rows `R-1`, `R-1i`, `D-1`, and `D-5` remain `"UNQUALIFIED"`.
   - `P5` assessment remains `"UNTRUSTED"`.
   - The host wire's caller semantics (`R1–R5` in `first_app_p3_host.py`) are unchanged.
